# آموزش قابل‌بازتولید روی MNIST

این پروژهٔ مستقل، یک CNN کوچکِ تألیفی را روی تصویر رقم‌های دست‌نویس آموزش
می‌دهد. وزن فیلترها با پس‌انتشار تغییر می‌کند؛ این گام بعد از آزمایشگاه دستیِ
کانولوشن است. معماری ReLU و max pooling دارد و بازسازی LeNet-5 تاریخی نیست.
اجرای آن به Python و PyTorch نیاز دارد و در صفحهٔ Shinylive اجرا نمی‌شود.

## پیش از اجرا

از ریشهٔ مخزن، محیط قفل‌شده را بساز:

```sh
uv sync --project deep-learning/labs/cnn-mnist --frozen --python 3.12
```

نسخهٔ PyTorch برابر 2.13.0 است. Linux و Windows از مخزن رسمی چرخ‌های CPU
استفاده می‌کنند؛ macOS بستهٔ رسمی PyPI را می‌گیرد. مسیر تأییدشدهٔ این درس CPU
است؛ شتاب‌دهنده شرط اجرا نیست. دانلود وابستگی‌ها از اجرای کوچک آموزش بزرگ‌تر
است. فایل‌های داده حدود ۱۲ مگابایت حجم فشرده دارند.

این اجرای کوتاه، سلامت کد را بررسی می‌کند:

```sh
uv run --project deep-learning/labs/cnn-mnist python deep-learning/labs/cnn-mnist/train.py --smoke --download --output deep-learning/results/mnist-smoke-1
uv run --project deep-learning/labs/cnn-mnist python deep-learning/labs/cnn-mnist/train.py --smoke --output deep-learning/results/mnist-smoke-2
python3 deep-learning/labs/cnn-mnist/verify_smoke.py deep-learning/results/mnist-smoke-1/report.json deep-learning/results/mnist-smoke-2/report.json
```

حالت `--smoke` فقط یک دوره روی ۶۴۰ تصویر آموزش، ۱۶۰ اعتبارسنجی و ۳۲۰ آزمون
می‌رود. پایین‌بودن دقت آن خطای برنامه محسوب نمی‌شود؛ این حالت برآورد عملکرد
آموزش کامل نیست. مقایسهٔ دو اجرا، تنظیمات، جداسازی داده، تاریخچه، نتیجه و هش
وزن‌ها را بررسی می‌کند. هر خروجی باید پوشه‌ای تازه یا خالی باشد.

## آزمایش اصلی

پیش‌بینی کن: شبکهٔ دارای فیلتر مکانی در برابر مدل خطی چه خطاهایی را کمتر
می‌کند؟ سپس دو اجرا را با تقسیم یکسان داده انجام بده:

```sh
uv run --project deep-learning/labs/cnn-mnist python deep-learning/labs/cnn-mnist/train.py --download --output deep-learning/results/mnist-cnn
uv run --project deep-learning/labs/cnn-mnist python deep-learning/labs/cnn-mnist/train.py --model linear --output deep-learning/results/mnist-linear
```

پیش‌فرض، پنج دوره، دستهٔ ۱۲۸، Adam با نرخ ۰٫۰۰۱، بذر ۷ و یک رشتهٔ CPU است.
با `--epochs`، `--batch-size`، `--learning-rate` و `--seed` می‌توان آزمایش را
تغییر داد. مقایسه با نرخ یکسان، اثبات بهینه‌بودن تنظیمات هر دو مدل نیست.

| مدل | مسیر داده | پارامتر |
| --- | --- | ---: |
| خطی | ۷۸۴ مقدار ورودی و ۱۰ logit | ۷۸۵۰ |
| CNN تألیفی | Conv 1→8، ReLU، pool؛ Conv 8→16، ReLU، pool؛ سر 784→10 | ۹۰۹۸ |

مقدار پیکسل بر ۲۵۵ تقسیم می‌شود. خروجی سر، logit است؛ تابع cross entropy
خودش محاسبهٔ پایدار لازم را انجام می‌دهد و پیش از آن softmax اضافه نمی‌شود.
شبکه در هر دوره فقط دادهٔ آموزش را می‌بیند. خطای آموزشِ ثبت‌شده پس از پایان
دوره دوباره اندازه‌گیری می‌شود؛ `online_training_loss` میانگین خطاهای حین
به‌روزرسانی است و معنای متفاوتی دارد.

## جداسازی و انتخاب مدل

مجموعهٔ رسمی ۶۰۰۰۰تایی، با بذر ثابت و جداگانه در هر کلاس، تقریباً به ۹۰٪
آموزش و ۱۰٪ اعتبارسنجی تقسیم می‌شود. گردکردن تعداد هر کلاس باعث می‌شود
اندازه‌ها دقیقاً ۵۴۰۰۰ و ۶۰۰۰ نباشند؛ تعداد واقعی و هش ترتیب اندیس‌ها در گزارش
آمده است. این تقسیم در سطح تصویر است؛ جداسازی نویسنده برای اعتبارسنجی ادعا
نمی‌شود. شناسهٔ نویسندگان در فایل‌های IDX این پروژه موجود نیست.

کمترین cross entropy اعتبارسنجی، checkpoint را انتخاب می‌کند. مجموعهٔ رسمی
۱۰۰۰۰تاییِ آزمون پس از این انتخاب بارگذاری و فقط یک‌بار ارزیابی می‌شود. انتخاب
معماری یا تنظیم دوباره پس از دیدن آزمون، دیگر ارزیابی مستقل نیست. بذر ثابت
تضمین برابری عددی بین سخت‌افزارها یا نسخه‌های متفاوت کتابخانه نیست.

## گزارش و بازسازی

هر اجرا `report.json` و `weights.pt` می‌سازد. گزارش، نسخه‌ها، معماری، بذر،
تعداد نمونه‌ها، هش اندیس‌ها، تمام دوره‌ها، checkpoint منتخب، ماتریس درهم‌ریختگی،
recall هر کلاس، macro recall و نتیجهٔ آزمون را نگه می‌دارد. دقتِ برچسب با
احتمال درست‌بودن یک پیش‌بینی واحد یکسان نیست.

هش SHA-256 کد، قفل وابستگی و داده‌ها ثبت می‌شود. هش پارامترها از مقادیر
float32 و شکل tensorها ساخته می‌شود؛ با هش فایل checkpoint یکسان نیست.
برای بارگذاری وزن‌ها از `torch.load(..., weights_only=True)` استفاده کن.
نتیجهٔ شخصی را با تنظیمات و نسخه‌ها نگه دار؛ فایل‌های خام و نتیجه‌های حجیم
خودکار به سایت منتشر نمی‌شوند.

## تمرین و مرز تفسیر

1. تعداد پارامتر هر لایه را مستقل حساب کن و با گزارش مقایسه کن.
2. دقت آموزش، اعتبارسنجی و آزمون را کنار هم بنویس. آیا افزایش دوره، همیشه
   اعتبارسنجی را بهتر می‌کند؟ چرا آخرین checkpoint لزوماً انتخاب نمی‌شود؟
3. از ماتریس درهم‌ریختگی، recall رقم‌های ۳ و ۸ را بازحساب کن. آیا دقت کلی،
   رفتار هر کلاس را نشان می‌دهد؟
4. برای آزمایش نرخ یادگیری، پیش از مشاهدهٔ آزمون یک طرح انتخاب کن و تصمیم‌ها
   را از روی اعتبارسنجی بگیر. محدودیتِ تکرار آزمون عمومی را توضیح بده.

این مسئلهٔ معیارِ کوچک، عملکرد روی جمعیت‌ها یا کاربردهای دیگر را تضمین
نمی‌کند. نتیجهٔ این CNN، نتیجهٔ LeNet یا AlexNet نامیده نمی‌شود. نتیجه‌های
اجراییِ منتشرشده باید به همان تنظیمات، هش کد و نسخهٔ داده ارجاع دهند.
