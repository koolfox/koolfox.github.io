Extend `src/tnf_atlas/` with a peptide-workbench package and CLI subcommands; leave `docking/` and its CRP record independently reproducible. Start without a daemon: one CLI command executes the frozen experiment and writes a self-contained local bundle under ignored `results/peptide-workbench/<experiment-id>/`.

Attach the reader to **Research → TNF peptide experiments** using `data/metadata/site-sections.json`, `scripts/build_section_pages.py`, existing templates and `research.html`/`structures.html` navigation. An assets subpage can be reached from those existing surfaces and is already inside the builder's tracked-assets allowance. Do not create a hidden parallel portal or repurpose the general `docking.html` lesson as the new research project. A new root HTML filename would require a separately scoped publication-builder change; prefer existing pages/assets to satisfy the structural-only boundary. Keep Arad/RTL; isolate sequence, author identifiers, commands and coordinate tables in LTR spans. Reuse the existing viewer and editor patterns without rewriting the entire UI. [Current navigation registry](https://github.com/koolfox/koolfox.github.io/blob/ec9ce745f8b4db8f9d8fe7ea5b1eeed43ced5eea/structural-bioinformatics/data/metadata/site-sections.json)

Pages may validate/export/import files and render completed results, but cannot host a persistent native engine, durable queue or private upload store. Browser Python/WASM computation is genuine client computation with browser lifetime/package/resource constraints; it is not evidence that a native docking package runs there. Native execution must not accept editable lesson code as an executable job payload. A later worker may watch a local queue directory; a localhost HTTP bridge is optional future scope, never a prerequisite or silently exposed network service. No engine work is triggered by a page visit or by normal Pages deployment.

#### Proposed pipeline, with explicit stops

1. **Acquire and inventory exact inputs.** Accept local PDB/mmCIF bytes or an explicitly requested archive download; preserve the original unchanged. Record accession/version if available, source URL, UTC, byte size and SHA-256. Validate format/content rather than trusting suffix; reject empty, truncated, nonfinite or inconsistent coordinates with diagnostic locations. Prefer mmCIF as the lossless working representation; do not silently force a PDB export when chain/residue/atom fields cannot represent the structure. Give size/model/atom-count limits and unsupported-format errors.
2. **Select models, components and assembly.** Inventory every coordinate model and require an explicit model number or declared ensemble; preserve source model number separately from a parser's zero-based index. Show author and label chain namespaces, polymer/entity IDs, residue insertion codes, sequence/coordinate gaps, missing atoms, alternate sites, occupancy, waters, ions, ligands, cofactors, covalent links and disulfides. Keep a reversible atom/residue map. Distinguish deposited ASU, official assembly and reconstructed crystal neighbours; every generated copy needs parent chain, operator, lattice shift and transformation matrix. Never use nearest neighbours as a generic biological assembly rule. For 3WD5 retain the existing specialized, validated reconstruction and distinguish it from the identity assembly record.
3. **Resolve selection policies before preparation.** Highest occupancy per atom can create an incompatible mixed residue conformation; introduce a residue-consistent altloc policy with an explicit tie rule or separate branches. Unknown/nonfinite/out-of-range occupancies require a decision/error; zero occupancy is unavailable geometry and must not become a modeled atom silently. Do not average alternate conformers. Choose chains explicitly, inventory omitted components, and keep unknown identifiers distinct. Never join chains, bridge a gap, renumber away insertion codes, or reconstruct missing residues automatically. A required unsupported/missing region stops preparation; a deliberately excluded region remains documented.
4. **Prepare a new derived structure.** Record every retained/removed water, ion, cofactor and ligand, with a reason and residue mapping; raw files remain available. A contact-analysis exclusion is not authority to strip components from a docking receptor. The CRP preparation preserves calcium but removes waters/non-PC heterogens by its own case-specific rule; do not generalize its `waters` bucket to arbitrary structures. [Existing split](https://github.com/koolfox/koolfox.github.io/blob/ec9ce745f8b4db8f9d8fe7ea5b1eeed43ced5eea/structural-bioinformatics/docking/prepare_redock.py#L49-L62) Preserve unsupported important cofactors and stop, or require an explicitly different experiment. Declare hydrogens, target pH/protonation/tautomers, termini/caps, charge assignment, disulfides, force field/parameters, minimization/frozen atoms and tool versions. Modeled atoms must be marked as modeled. Produce before/after inventories, coordinate displacement summary and output hashes; no silent repair or hydrogenation. Removing Fabs from a TNF receptor is an explicit experimental component decision, with the original complex retained as a reference.
5. **Generate bounded sequences and real peptide structures.** Normalize whitespace/case with a visible transformation log; initially accept the 20 canonical L-amino-acid letters only. Reject ambiguous codes, noncanonical/D residues, cycles and modifications as unsupported until separately implemented. Require an ordered sequence or explicit positional sets/lengths: an unordered amino-acid list alone is not a unique peptide experiment. For a parent of length L, all single substitutions are **L × 19** unique mutants (plus the parent if included), not 20^L. A complete length-L canonical library is **20^L**, including the parent. Exact k substitutions number C(L,k)19^k; positional sets produce the product of their sizes before deduplication. Use integer arithmetic and lazy enumeration; show requested, valid, unique, rejected and scheduled counts before materializing work. Deduplicate by sequence **and chemical identity** (termini, chirality, modifications), retaining all parent/generation paths. Hard limits cover sequence count, conformers, receptor/preparation states, sites, seeds, poses, bytes, RAM, CPUs and elapsed-time budget; exceeding a limit fails planning instead of silently truncating or randomly sampling.
6. **Build and sample conformers.** Construct actual peptide bonds, terminal groups and new side-chain atom identities/coordinates. For substitutions, either rebuild the whole free peptide or mutate a declared template followed by explicit side-chain building, rotamer/repacking and bounded relaxation; name which neighbours/backbone may move. Validate sequence, bond graph, atom completeness, stereochemistry, clashes and finite geometry. A deleted side chain is never a completed mutation. Keep template-derived and de novo conformers labeled separately. Use multiple declared starts and seeds; save accepted/rejected conformers and clustering decisions. These are sampled hypotheses, not independent biological replicates or estimated equilibrium populations. If an engine folds from sequence internally, record that sampling explicitly; never claim it consumed an external conformer it ignored. Unsupported initial-coordinate/chemistry modes stop the adapter.
7. **Execute jobs and analyze only real outputs.** One job identifies variant chemistry, conformer/start, receptor state, site, engine, parameters and seed. Save argv, working-relative paths, binary hash/version, environment lock/platform, stdout/stderr, exit status, elapsed time and output checksums. Grid caches include receptor/preparation hash, box, resolution, engine and all required atom types. No shared mutable scratch files. Classify preflight rejection, unsupported capability, engine failure, timeout, cancellation and interrupted process separately. Parse finite coordinates and expected sequence/atom mapping before accepting poses; zero poses is explicit, not success with a fabricated score. Analyze pose-specific contacts/SASA/clashes using declared atom sets and units. Preserve raw engine score names/direction; do not rename a ranking score to measured affinity or combine incompatible engines' values into one rank.

Use `planned → queued → running → succeeded` with explicit terminal alternatives above; invalid specifications are rejected before queueing. A successful engine invocation may still **fail a scientific validation gate**, as the existing CRP score-separation check did; do not confuse scientific failure with process failure. Cancellation terminates the child process group, preserves logs/partial artifacts labeled incomplete, and cannot later be overwritten by a late success event. Resume verifies immutable input/output hashes and atomically completed outputs; a changed input invalidates reuse. Local files/SQLite may back the queue; no remote service is necessary.

Imports validate supported schema major versions, cross-file IDs, hashes, coordinate maps and terminal states. Unrecognized major versions are explicitly unsupported. Optional new fields can be forward compatible within a documented minor version. Imported reports are data, not executable Python/shell. Bundle readers enforce file/count/size bounds and safe relative paths. The viewer must use the same exact pose artifact as the downloadable report, show both author and peptide-position identities, and distinguish original, prepared, generated and docked structures. Edited inputs invalidate prior displayed results. Export failures and unavailable WebGL/storage still leave tables, logs and downloads accessible.

#### Reproducibility, licensing and migration rules

Record seeds for sequence sampling if enabled, conformer generation, docking and any stochastic relaxation separately. Pin actual engine/build/adapter/environment versions and parameters; preserve input/output bytes. Fixed seed alone is not a cross-platform bitwise reproducibility guarantee. New code must not use a guessed version fallback: the existing Vina runner's fallback string is a historical implementation detail, not a sufficient new execution attestation. [Existing version recording](https://github.com/koolfox/koolfox.github.io/blob/ec9ce745f8b4db8f9d8fe7ea5b1eeed43ced5eea/structural-bioinformatics/docking/run_vina.py#L86-L99)

Keep wwPDB citation/CC0 provenance as recorded, vendor notices (including Mol* and editor libraries), and a per-component manifest for the selected builder, engine, rotamer/force-field data, dependencies and distributed example structures. Do not inherit the unrelated `deep-learning/LICENSE` for structural code or assume the entire ADFR suite has one permissive license. ## 3. What are the six increments and a defensible pilot?

### Takeaway

Ship six independently reviewable increments with pass/fail evidence, not dates or predicted run times. Start with contracts and exact structure inspection; enable real local peptide execution only after building, compatibility and benchmark gates. The pilot tests transparency and execution, not therapeutic efficacy.

### Cited Findings

- Existing meaningful numerical controls include contact cutoff/rigid-motion/occupancy tests; analytic SASA sphere/cap and separation checks; crystal-symmetry/Kabsch/CDR/reconstruction checks; curated coordinate/provenance checks; and browser reader/editor/lab/isolation suites. Extend those controls rather than replacing them with record snapshots.
